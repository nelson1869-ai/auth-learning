## Ano ang nahuli ng TypeScript
| Saan | Error | Ayos |
|---|---|---|
| `drizzle.config` | `string \| undefined` → `string` (`DATABASE_URL`) | fail-fast na may malinaw na mensahe |
| unit test | `result.data` is possibly `undefined` | `parse()` kapag inaasahang papasa |
| `requireAuth` | ang `jwt.verify` ay puwedeng `string` o walang `sub` | tanggihan ang dalawa (401) |
| `auth.js` (5 error kung pinalitan lang ang pangalan) | `err` is `unknown` · `JWT_SECRET` undefined ×2 · `req.userId` undefined · `sameSite: string` | `isUniqueViolation()` · `env.JWT_SECRET` · suriin ang `userId` · `CookieOptions` |
| API test | puwedeng walang `Set-Cookie` | `res.get('Set-Cookie')?.[0]` |

## Ano ang natutunan ko (sa sarili kong salita)
- **`unknown`** (sa `catch`) = suriin muna ang hugis bago gamitin. Mas ligtas kaysa `any`.
- **`z.infer`** = iisang source: ang Zod schema ang validation AT ang type.
- **`config/env.ts`** — ipinakita ng TypeScript na bawat `process.env.X` ay puwedeng `undefined`; kaya sinusuri silang lahat pagka-start. Maikling `JWT_SECRET` → hindi mag-i-start ang server.
- **Declaration merging** (`types/express.d.ts`) — dinadagdagan ang type ng library (hal. `req.userId`).
- **Walang `!`** (non-null assertion) — suriin ang value, huwag hulaan.
